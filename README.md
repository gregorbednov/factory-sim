# Factory Sim

Промышленный симулятор на Rust с настольным редактором и браузерной демкой. Один проект запускается в 3D-редакторе, из CLI или через MCP. Демонстрационная сцена включает конвейеры, фотоэлектрический датчик, толкатель, подачу и удаление коробок, боковой отвод и ограждение.

## Попробовать онлайн

Откройте [Factory Sim Online](https://gregorbednov.github.io/factory-sim/) в браузере с WebGPU или WebGL2. В демке доступна ячейка со станком и роботом. На паузе откройте **Библиотеку элементов**, чтобы добавить оборудование или изделие из общего с настольной версией каталога. Нажмите на карточку или перетащите её на сцену. Размещённое оборудование привязывается по ходу потока при перетаскивании. Кнопка **Один шаг симуляции** продвигает физику на один такт (1/120 секунды). Если сцену изменили, следующий пуск или шаг применяет изменения с начала прогона. JSON можно загрузить с диска или скачать из браузера.

Веб-сборка не подключается к ПЛК. Драйверы OPC UA и Modbus TCP, CLI, MCP через stdio и импорт STEP/OBJ/STL доступны в настольной сборке. Готовые модели из JSON появляются в браузерной библиотеке и доступны для размещения.

Для локальной сборки установите целевую платформу Rust и версию `wasm-bindgen` из `Cargo.lock`:

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --locked --version 0.2.130
scripts/build-web.sh
python3 -m http.server 8080 --directory target/pages
```

Локальная страница откроется на [localhost:8080](http://localhost:8080/). Рабочий процесс [Factory Sim Pages](.github/workflows/pages.yml) собирает и публикует сайт из ветки по умолчанию. В настройках GitHub Pages источником должны быть GitHub Actions.

## Запуск

Соберите приложение с актуальным стабильным Rust и Cargo. Полная сборка включает редактор, OPC UA и MCP. На NixOS команда `nix-shell` добавляет компилятор и динамические зависимости окна и графики.

```bash
cargo build --locked
cargo run --locked -- studio examples/sorting.json
cargo run --locked -- validate examples/sorting.json
cargo run --locked -- run examples/sorting.json --ticks 1200
cargo run --locked -- run examples/sorting.json --ticks 1050 --script examples/divert-first.json
cargo run --locked -- run examples/sorting.json --seconds 10 --trace-every 120
```

`studio` без аргумента открывает встроенную демонстрационную сцену. Vulkan используется по умолчанию. На Linux и Windows OpenGL выбирается в «Настройках» и применяется при следующем запуске. Разово можно указать `studio --backend opengl` или `studio --backend vulkan`. На macOS для редактора требуется установленный Vulkan Loader и видимый ему ICD MoltenVK. Запуск без окна обходится без графического адаптера. Для сборки без графических зависимостей с сохранением OPC UA и MCP используйте `--no-default-features --features opcua,mcp`.

В прогоне с `divert-first.json` стартовая коробка проходит через боковой отвод. Счётчик `side_exit.count` в итоговом JSON равен 1.

Кнопка «Новый» создаёт пустую сцену. В редакторе выберите деталь в дереве или на сцене. Инспектор позволяет менять геометрию, рабочие параметры и имена тегов. При остановленной симуляции деталь можно перетащить по плоскости. Чтобы удалить выбранную деталь, нажмите `Delete` или выберите «Удалить объект» в свойствах или в контекстном меню списка «Сцена». Сохранение проекта включает удаление связанных тегов и их привязок к ПЛК. Правая кнопка вращает камеру, Shift с правой кнопкой сдвигает её, колесо меняет масштаб. «Пуск» применяет подготовленные правки и запускает физику. «Шаг» выполняет один шаг. «Сброс» восстанавливает исходные тела и команды и ставит сцену на паузу. Кнопка «Сохранить» записывает правки сцены и настроек ввода-вывода.

Русский язык включён по умолчанию. Через **Настройки → Язык** можно переключиться на English прямо в открытой сцене. Выбор сохраняется в настройках редактора. Имена объектов, импортированных моделей и тегов из файла проекта отображаются в том виде, в котором их сохранили. Поля JSON, команды CLI и идентификаторы ПЛК сохраняют прежний формат.

В **Настройки → Качество графики** выберите профиль для 3D-сцены. Он применяется сразу и сохраняется в настройках Studio.

- **Производительность**. Внутреннее разрешение сцены 80% по каждой оси, меньше сегментов у круглых деталей, без теней, отражений и MSAA.
- **Баланс** (по умолчанию). Полное разрешение, средняя детализация круглых деталей и тени 1024×1024.
- **Высокое качество**. Более гладкая геометрия, тени 1536×1536, отражения пола в половинном разрешении и 4× MSAA при поддержке адаптером.

Профиль графики задаёт только отрисовку. Расчёт столкновений, шаг симуляции и обмен с ПЛК используют свои настройки.

### Библиотека элементов

На паузе нажмите **Добавить**. В библиотеке есть поиск, категории и 3D-превью оборудования и изделий. Нажмите на карточку для добавления или перетащите её в нужное место сцены. В той же библиотеке доступны изделия, импортированные в проект.

Гравитационный лоток перемещает изделия под действием силы тяжести в направлении своей локальной оси X. Свободный ролик служит пассивной опорой между участками линии.

### Перемещение объектов

На паузе перетащите объект левой кнопкой мыши в сцене. Его высота сохраняется. Подъём и опускание задаются в инспекторе через координату Y. Рядом с совместимым входом или выходом включается привязка по ходу потока. Выравниватели и источники также привязываются к оси конвейера, а съёмники — к его концу. Удерживайте **Ctrl** для свободного перемещения или нажмите **Esc**, чтобы отменить перетаскивание.

### Изделия

На паузе откройте **Сцена → + Добавить → Изделия**. В каталоге есть стандартная и высокая картонные коробки, а также низкий пластиковый ящик. У каждого свои габариты и масса. Там же доступна команда **Импорт 3D-модели…**. Введите путь к модели или перетащите файл в открытый диалог, выберите единицы файла, вертикальную ось и массу. **Импортировать и разместить** добавляет изделие в каталог проекта и ставит первый экземпляр на сцену. В инспекторе эмиттера выберите его в поле **Изделие**, чтобы подавать такие же изделия.

Для B-Rep экспортируйте отдельную деталь в STEP (`.step` или `.stp`, одна оболочка). Также поддерживаются OBJ и STL. По умолчанию для STEP и STL выбраны миллиметры и вертикаль Z, для OBJ метры и вертикаль Y. Геометрия центрируется по габаритам. Проект хранит исходный текст STEP и тесселированную сетку, а для OBJ и STL хранит сетку. Импорт поддерживает геометрию без материалов и текстур. При столкновениях используется выпуклая оболочка, поэтому отверстия и вогнутости видны, но перекрываются коллайдером.

## Проекты, теги и ПЛК

[Демонстрационный проект](examples/sorting.json) использует JSON со схемой версии 1. Координаты и размеры в метрах, масса в килограммах, yaw в градусах вокруг вертикали. Конвейер и датчик направлены вдоль локальной оси +X, толкатель — вдоль +Z.

ID тега образуется из ID детали и роли, например `diverter.extend` и `diverter.front`. Отображаемое имя задаётся отдельно в `tag_names`. Теги Bool, Float32 и Int32 имеют направление и качество. Внешние источники могут изменять команды, а датчики доступны для чтения. В `initial_commands` задаются значения после сброса.

Пример содержит три готовых профиля. Включите нужный в редакторе через «ПЛК» или установите `"enabled": true` в файле и проверьте проект командой `validate`. Один и тот же управляющий тег может принадлежать только одному включённому драйверу.

| Профиль | Привязка |
|---|---|
| Modbus TCP-сервер | ПЛК пишет Coil 0 для толкателя, читает Discrete Input 0–2 для датчика и концевиков. Holding Register 0 задаёт скорость. |
| Modbus TCP-клиент | Симулятор читает Discrete Input 0 и Input Register 0. Coil 0–2 и Holding Register 0–1 передают состояния ПЛК. |
| OPC UA-клиент | Сопоставление по `NodeId`. Команды читаются с OPC UA-сервера, значения датчиков записываются на сервер. Узлы должны поддерживать соответствующий тип и доступ. |

Адреса Modbus в файле отсчитываются от нуля. Единица доступа задаётся `unit_id`. Регистры декодируются как знаковые 16-битные слова. Для Float вход делится на `scale`, а при передаче значение умножается на него. Преобразование на выходе отбрасывает дробную часть и насыщается на границе Int16. Командный Float ограничивается диапазоном тега. Для OPC UA профиль `security: {"mode":"none"}` использует анонимный сеанс, профиль `{"mode":"sign_and_encrypt","pki_dir":"./pki"}` выбирает Basic256Sha256 с доверенными сертификатами из заданного хранилища. Для защищённого сеанса проверенный сертификат сервера устанавливается в `pki_dir/trusted` под исходным именем из `pki_dir/rejected`. Профили в демонстрации по умолчанию выключены.

Сетевой обмен выполняется отдельно от шага физики. `poll_ms` задаёт желаемый период клиента, но не гарантирует доставку каждого импульса. При потере связи команды получают качество `stale`. `on_disconnect: "hold"` сохраняет последнее полученное значение, `"reset"` восстанавливает начальное. Новая принятая команда снова получает качество `good`.

## CLI и MCP

`run --ticks N` выполняет N фиксированных шагов без сетевого обмена. `--script path.json` принимает массив отсортированных команд вида `{"tick":240,"tag":"diverter.extend","value":true}`. Команда применяется перед соответствующим шагом. `--trace-every N` выводит периодические снимки JSON Lines и итоговый снимок. Без `--ticks` используется реальное время, а драйверы можно отключить флагом `--no-io`.

```bash
cargo run --locked -- mcp examples/sorting.json
```

MCP работает по stdio и начинает с паузы. Доступны `state`, `list_tags`, `read_tag`, `set_actuator`, `start`, `pause` и `reset`. `read_tag` принимает `id`, `set_actuator` — `id` и `value`. Состояние включает значения, качество, позиции грузов и статусы драйверов.

Планировщик физики рассчитан на 120 Гц и обрабатывает накопленные такты отдельно от кадров интерфейса. Буфер глубины, тени и отражение оборудования в полу вычисляются на GPU. Строка состояния показывает FPS и фактическую частоту симуляции. Для проверки независимости частот можно запустить редактор с `--run --fps-limit 30`. Модели и оформление редактора созданы для этого проекта.

## Производственная ячейка

Откройте `examples/production-cell.json` в Studio и нажмите **Пуск**. Источник подаёт заготовки на входные ролики со случайным смещением и поворотом. Пассивные направляющие выравнивают поток перед станком. Станок обрабатывает заготовки при наличии оператора. Робот вынимает детали из станка и раскладывает их по конвейерам годных изделий и брака. Годные изделия проходят через весы. Модельное время начинается за две секунды до смены. Ту же сцену можно прогнать на фиксированных шагах командой `cargo run --locked -- run examples/production-cell.json --ticks 7200 --trace-every 1200`.

### Оборудование и теги

- **Оборудование** содержит роликовый конвейер, выдвижной стопор, весы, ёмкостный датчик, световую завесу, сигнальную колонну, секцию ограды, защитную дверь, поворотный стол и цепной перегружатель. Ролики, весы и перегружатель двигают изделия в Rapier через скорость контактной поверхности. У транспортёров `forward` и `reverse` взаимно отменяются. У роликов при выключенных цифровых командах `speed_v` задаёт скорость аналогово. Поворотный стол работает в моностабильном режиме `turn` между 0° и 90° и показывает концевики. У цепного перегружателя `left` и `right` поднимают цепи и задают поперечное направление.
- Весы показывают массу непосредственно лежащих на измерительной плите изделий и напряжение до 10 В, предел 20 или 100 кг. Ёмкостный датчик показывает наличие детали и расстояние до 0,2 м. У световой завесы две стойки размещаются одной парой. Она отдаёт восемь отдельных лучей, маску и напряжение 0–10 В. Секция ограды и створка имеют коллайдеры. Дверь открывается командой `open`, сообщает `closed` и о препятствии при движении.
- Команды и состояния доступны как обычные теги `<ID детали>.<роль>` в инспекторе, CLI и MCP, для привязок OPC UA и Modbus TCP. Локальные идентификаторы и дополнительные сигналы относятся к Factory Sim. Описание механизмов сверено с [разделами Factory I/O](https://docs.factoryio.com/manual/parts/).

### Источники

В инспекторе источника **Режим подачи** выбирает одно изделие, точную серию или вероятности. В точной серии `A:3, B:1` каждые четыре исхода содержат три A и один B в случайном порядке. Строка **Пропуск** занимает слот серии. Отдельное правило **Пропуск до выбора изделия** пропускает попытку и оставляет серию на месте. В режиме вероятностей можно выбрать **Пропуск** явной строкой. Остаток до 100% тоже означает пропуск. Занятая зона источника задерживает попытку. Пропуск расходует интервал, увеличивает `skipped` и оставляет счётчик `count` прежним.

В JSON вероятности задаются числом 0–1 или строкой с выражением. В формулах `t` — секунды с начала прогона, `hour` — модельный час суток, `weekday` — день недели от 1 до 7. Например, `0.25 * (t < 120)` даёт 25% первые две минуты, а `(hour < 8) || (hour >= 16)` пропускает попытку вне дневного интервала. Каждый результат должен быть в интервале [0, 1], а сумма вероятностей — не больше 1. При неверном значении источник выставляет `recipe_error` и перепроверяет формулы на следующей попытке. **Производство** содержит `seed`. «Сброс» восстанавливает последовательности случайных исходов.

В поле **Случайная подача на конвейер** выберите ленту, роликовый конвейер или конвейерные весы. В JSON укажите идентификатор через `random_spawn_belt`. Положение источника задаёт точку вдоль конвейера. Источник сам выбирает высоту над поверхностью, поперечное смещение и поворот вокруг вертикальной оси, учитывая габариты изделия. Если свободного места нет, `spawn_blocked` включается, а источник сохраняет выбранное изделие до следующей попытки. Координаты и повороты воспроизводятся после сброса при том же `seed`.

### Пассивное выравнивание потока

Выберите **Добавить → Оборудование → Пассивный выравниватель потока**. Разместите его над конвейером, направив локальную ось X по ходу ленты. Нижняя кромка направляющих должна быть на уровне ленты или чуть выше. Задайте длину, высоту и ширину прохода на входе и выходе. Сходящиеся направляющие смещают и разворачивают изделия при контакте. Прямой участок на выходе удерживает выровненный поток. У слишком узкого прохода изделия могут заклинить.

В [демонстрационной сцене](examples/flow-alignment.json) источник подаёт изделия в разных положениях, а направляющие собирают их к середине ленты. Для прогона без Studio используйте `cargo run --locked -- run examples/flow-alignment.json --ticks 10800`.

### Станки, сборочные столы, роботы и персонал

- **Ручной сборочный стол** и **Автоматический сборочный стол** доступны в библиотеке в разделе **Станции и персонал**. В инспекторе укажите состав (BOM), количество каждого типа и модель готового изделия. Стол принимает компоненты с одного входа в любом порядке и начинает сборку после сбора полного комплекта. Допускается до 32 деталей на цикл. Бракованная, лишняя или неподходящая деталь остаётся на приёмном порту и вызывает `input_error`. Теги `waiting_material`, `material_count` и `required_count` показывают состояние комплекта. Подайте фронт `start`, как для станка.
- Ручному столу нужен оператор на смене в том же участке. Автоматический работает без оператора. Оба используют настройки времени цикла, вероятностей отказа и брака, времени ремонта с наладчиком, защитной двери и выгрузки на выход годных изделий или брака. После сборки комплект становится одним изделием в рабочей зоне. Его переносит на выход оператор, встроенный захват автоматического стола или назначенный робот. Следующий комплект поступает в работу после освобождения стола.

- В **Станции и персонал** доступны обрабатывающий центр, XYZ и двухосевой Pick & Place, оператор и наладчик. Станок принимает одну деталь по типу изделия. Три порта задаются в локальных координатах, высота порта соответствует поверхности опоры. Длительности цикла и ремонта выбираются в секундах, минутах или часах. Встроенный захват поднимает заготовку с приёма, переносит её в рабочую зону и после обработки вынимает тот же объект. В рабочей зоне обновляются геометрия и масса. Время перемещения добавляется к длительности обработки. При занятом выходе захват удерживает деталь до освобождения порта. Брак с меткой `scrap` выгружается на отдельный выход, для него можно выбрать свою модель.
- `start` запускает станок по фронту, `stop` останавливает обработку, `emergency` фиксирует аварийную остановку. После снятия аварийного сигнала подайте фронт `reset`, затем новый фронт `start`. Дверь и отсутствие оператора приостанавливают обработку. Случайный отказ проверяется один раз за цикл. При срабатывании он происходит в случайный момент работы, после ремонта обработка продолжается с накопленного времени. Вероятность брака проверяется при завершении работы и сохраняется, пока выход занят.
- Чтобы робот разгружал станок, выберите его в поле **Выгрузка** инспектора станка или задайте `machine.unload_robot` в JSON. Укажите `outlet` и `reject` на поверхностях соответствующих конвейеров в локальных координатах станка. Рабочая зона, обе точки и траектория подъёма должны быть в пределах хода захвата. При укладке деталь должна целиком помещаться за пределами станка. Если эти условия не выполняются, робот выставляет `out_of_reach`, а деталь остаётся в станке. Без назначения используется встроенный захват.
- Подайте `start` станку и роботу. Назначенный робот автоматически обслуживает готовые детали. Станок выставляет `waiting_unload` и ждёт, пока робот вынесет деталь из рабочей зоны. Если выход занят, робот держит деталь над ним. Счётчики станка обновляются после укладки. При остановке робота деталь остаётся на месте и перенос продолжается после нового фронта `start`.
- В программе робота доступны перемещение, поворот захвата, выдержка, ожидание внешнего сигнала, захват и отпускание детали. Захват ждёт деталь у инструмента. Отпускание ждёт освобождения места. Размеры рабочей области ограничивают допустимые точки программы. Порядок действий задаёт программа. Теги ПЛК запускают и останавливают её, подают сигнал и читают положение или состояние.
- Человек назначается на участок по имени и получает календарь. Один дежурный оператор наблюдает за станками своего участка. Один наладчик обслуживает один станок, начиная с наиболее раннего отказа. Вне смены прогресс ремонта сохраняется и работа может продолжиться при появлении наладчика. Наличие на участке определяется расписанием. Координата человека используется для его размещения на сцене. Ходьба и расчёт маршрутов запланированы отдельно.
- В **Производство** можно задать начальную локальную календарную дату и создать шаблон смены. `weekly` содержит дни недели 1–7 и минуты от начала суток, конец интервала исключён. Конец раньше начала обозначает ночную смену. `overrides` переопределяет работу на конкретную дату, пустой список означает выходной. Время следует за тактами симуляции, останавливается на паузе и не зависит от часов компьютера. При отсутствии назначенного календаря сотрудник вне смены.
